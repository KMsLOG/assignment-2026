## 사용자 프롬프트 기록 (원문)

1. problem.md 파일에 대한 요구사항을 분석해줘
2. 그러면 docs에 REQUIREMENTS.md 파일 만들어줘
3. 프로젝트 구조에 맞게 /src로 소스코드 이동시키자
4. 우선 데이터를 구축해야하는데 mysql로 db를 설정하는데 이걸 docker로 구동하고 데이터 제약에 맞는 데이터를 생성할 수 있는 SQL문도 있으면 좋을 것 같아
5. 이거에 맞게 데이터 생성하는거 맞지?
6. 그래 맞춰줘
7. 이번 변경 커밋메세지 알려줄래
8. 영어로
9. 이제 그렇다면 필요한 기능들에 대해 api를 만들꺼야 /api는 컨트롤러, /services는 비즈니스 로직, /domain에는 dto나 schemas 가 있도록 하고 /repository에는 데이터를 접근하도록 할꺼야 그리고 SQLAlchemy를 사용하자 그리고 /core에는 globalexceptionhandler를 만들어서 예외사항을 처리하자
10. 한꺼번에 커밋을 하게 되면 이게 무엇을 적용햇는지 파악하기가 어려울꺼 같아 의미 있는 단위로 커밋할 수 있도록 하는 것이 좋을 거 같아
11. 이렇게 기능별로 나눠서 다시 커밋 가능?
12. 해당 기능들이 잘 구현되었는지(제약사항, 우리가 지정한 암묵적 결정사항)에 대한 테스트코드를 작성하고 테스트를 진행하고 이걸 커밋해줘
13. 제출물 구조에 맞게 프로젝트 구조 알맞게 해줘
14. api 문서 한글로 바꾸주고  OpenAPI(Swagger) 형식으로 해줘
15. 이거에 맞게 api문서 만든거지?
16. 그러면 커밋해줘
17. api 문서를 md 파일로 볼 수 있도록 해줘
18. 커밋해줘
19. README.md 파일을 프로젝트 빌드 방법 / 서버 실행 방법 / API 서버 접속 정보 (포트 등) 로 구성되도록 변경해줘
20. 프로젝트를 전부 docker 실행하게 하도록 하자 그리고 db에서 MYSQL_USER: app ,MYSQL_PASSWORD: app 와 같은 민감한 정보 같은 경우는 .env를 활용하도록 하고 이걸 readme에서 안내하도록 하자 이를 의미 있는 단위로 커밋으로 진행해도록 해줘
21. .env에 어덯게 들어가야하는지 예시를 추가해주면 좋을꺼 같아
22. 커밋해줘
23. 목록조회 같은 경우 커서기반 페이지네이션과 오프셋기반 페이지네이션 중 어떤걸로 선택해야하는지 성능적인 측면 주로 어떤 상황에서 이용할지에 대해 비교해서 어떤걸로 선택하는 것이 맞을까?
24. 그렇다면 커서기반페이지네이션으로 바꿔서 적용해주고 requirements.md에 변경한 내용도 반영해주고 커밋을 의미있는 단위로 해서 커밋해줘
25. 적용해서 의미있는 단위로 커밋해줘
26. 너한테 입력한 프롬프트를 prompts/codex.md 파일에 추가해줘
27. 이전에 입력한 모든 프롬프트 정리해서 넣어줘
28. 해당 평가 내용에 맞게 잘 구현되었는지 확인하고 평가해주고 부족한 부분 있으면 알려줘
29. codex.md 업데이트 해주고 해당 사항들 반영해서 의미있는 단위로 커밋해줘
30. codex.md 에서는 내가 직접 기록한 프롬프트만 넣어줄수 있도록 해줘
